# Security Policy

Do not file public issues for security vulnerabilities.

Email [security@YOUR_ORG.com](mailto:security@YOUR_ORG.com) with:
- A clear description of the issue
- Impact assessment (what can be compromised)
- Reproduction steps or proof-of-concept
- Affected version/commit and environment details

## Disclosure Process
1. The security team acknowledges receipt and starts triage.
2. Vulnerabilities are classified by severity and exploitability.
3. A coordinated remediation and disclosure timeline is agreed where possible.
4. Fixes are released with least-privilege and regression-test validation.

## Handling Rules
- Never include production secrets in reports.
- Use temporary or revoked credentials in proof-of-concept payloads.
- Prefer encrypted channels for sensitive exploit details.
